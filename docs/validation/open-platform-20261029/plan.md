用户授权范围：补齐此前核查的全部缺口，包括公开 REST/WebSocket 接入文档与顶部入口、API Key 管理与权限/IP 策略、API Key 私有 WebSocket 接入、整个 Gateway 的限频限流。仅验证相关功能，不执行压测、JMH/JFR 或全量测试。

## 完成条件

1. 公开文档页面及桌面/移动菜单入口，不要求登录；按实际协议提供六产品、精度、签名、权限、错误、限流、幂等及 WebSocket 快照/增量/重连说明，示例可以真实执行。
2. API Key 创建、列表、编辑名称/权限/IP、撤销完整闭环；安全验证码保留；写权限必须绑定 IP；密钥只创建时显示且加密保存；撤单要求 TRADE；撤销和权限/IP 修改影响后续 HTTP 与已连接的私有 WS。
   原生 Gateway 交易/账户接口支持六产品 API Key 认证，签名绑定方法、路径、查询和正文摘要；兼容 API 保留原签名。API Key 不能调用管理写接口或跨用户划转。
3. API Key 可使用短时、一次性签名凭证认证私有 WebSocket，不把秘密放入 URL；绑定用户、来源 IP、权限和有效期；原 JWT 客户端继续使用原协议；私有订阅不得跨用户或产品串线。
4. 所有外部 HTTP 路径先按真实 IP 限制；鉴权后的用户/API Key/产品配额覆盖原生、代理和兼容 API，业务别名共用额度；批量按项目计费；撤单/回执独立额度；多 Gateway 共用 Valkey 原子计数。
5. Gateway 并发、WS 新建连接/同时连接/入站消息有限；既有发送队列与订阅上限保留；配额有 TTL 和边界；存储故障和配额耗尽区分；429 带 Retry-After，WS 有明确错误和关闭策略。
6. 限流在业务提交前拒绝，未知结果/幂等与资金恢复语义保持；后台、Web 和 App 错误提示与契约同步；Nginx、中文 README 与部署说明同步。
7. 相关单元/数据库/Valkey/HTTP/WS 测试通过；Web lint/typecheck/相关测试/build 通过并真实浏览器桌面与窄屏验收；受影响 App analyze/测试及设备交互验收；记录证据与未测范围，不以编译代替交互。
8. 只提交本轮改动，保留其他任务的返佣文件；验证后按各仓库现有分支提交推送；归档日志后清理本轮临时资源。
