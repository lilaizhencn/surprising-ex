# 多团队与多实例返佣验证计划

执行范围说明（2026-10-29）：按用户要求，本轮只运行相关功能测试与编译；下文规模专项、JFR、长稳与完整网络链路均未执行。实际命令、结果和限制以 [README.md](README.md) 为准，此文件保留最初计划，不代表已完成验收。

起点 master `2e37775ef`，JDK 27 / PostgreSQL 18；不回跑旧提交，不修改交易在线 Core。CodeGraph MCP 工具当前不可用，检查已定位的返佣源文件。

先验证同一产品中异常团队对其他团队的影响。现有实现按产品事务核算，关系异常会令本产品整批回滚。新回归先确认现状；修复须保留坏费用完整事实与原确认断点，不能将隔离理解为丢弃、零佣金或已结算。

在 Gateway 内对可明确识别的关系异常持久化隔离，分别记录接收与确认游标；健康团队可继续。金融身份冲突、数据库错误仍整体回滚。隔离记录有不可变事实、容量上限、有界重试和成功凭证，管理员能区分已接收与待核算；不修改交易消息或手续费投影。

功能门槛：同产品坏团队不影响健康团队；坏费用无任何部分佣金；接收游标推进必须已有完整佣金或隔离事实，确认游标不能跨越未解决费用；修复后按原费用身份、原发生时间补算且不重复付款。多实例、进程重启、并发配置、资金未知结果、不同产品/资产、隔离队列满均验证安全边界。

规模专项：确定性种子 20261029；常规 1000 个独立团队、每队 50 名客户，团队深度混合 1/3/6，附一个 256 节点热点团队；六产品线、每队每产品 2 笔费用，共约 12000 事实。对照 10000 个小团队，客户总规模相近。使用 4 个独立 Spring 容器/连接池共享 PostgreSQL，后台核算与结算同时竞争任务，验证全部团队账目、幂等和排空；这是多实例业务组件验证，不宣称 4 个完整 Gateway 网络进程。

先无 profiler 主运行，再独立 JFR profile（64MiB）同负载诊断。记录费用完成/隔离/积压、批次时延分位与 max、峰值连接、锁等待、GC/CPU/heap、全系统换页、资金差额；发压/故障注入与测量/排空分开。不通过闭环倒数宣称交易 TPS，不将有换页/采样缺口的耗时当正式容量结果。

真实 Core 资金状态机用于多团队付款与丢响应恢复；未跑的真实 Aeron 网络、三节点、长稳及正式单成员/单 Matcher/in-flight256 链路明确列为未测。归档命令、摘要和失败过程，清理独立数据库/进程，验证后按项目规范提交推送。

万队运行前补充锁定：10000 队全部在 SPOT 活动、每队 5 名客户与 2 笔费用，总 20000 笔。它专门验证同一产品的共享锁、游标和 Core 资金身份在大量团队下的行为；不是把 1000 队六产品运行吞吐按十倍外推。仍用四业务容器、双资产、256 节点热点、全量付款与快照恢复。保持无 profiler 主运行，之后另跑 1000 队六产品 JFR 诊断。
