# 单 Aeron 节点永续饱和压测（2026-10-28）

## 1. 结论与场景

**饱和验收失败；速度正式验收无效；Core饱和未确认（UNCONFIRMED）。** 本次为真实网络的纯批量交易基准（Clustered Batch Trading）：保留UDP、单成员Consensus、Archive/WAL、Core、一个Matcher、两个Account Lane。16线程档在预热出现标记价过期拒单，按零拒单门槛失败；其余稳定窗均有系统换页和CPU限频，不能当作Core极限、三节点容量或性能提升。

当前master `161ef228e5bf17c460dd1f7552865df9f720f03d`，开始时工作区干净，没有修改生产代码。环境：Corretto HotSpot 27+33-FR、Maven3.9.16、G1、i9-9880H、8核16线程、16GiB、64B缓存行。开始前磁盘可用213GiB，系统已有约7.8GiB swap。

锁定LINEAR_PERPETUAL、10,000个预充值账户、256币对、seed9901、买卖GTC各半、每批20单、无外部做市。全局256报文窗口，最多5,120业务订单在途；账户不保证同时活跃，实际非零持仓另列。每档新节点，预热30s、测量60s、排空单列、各一次；4线程同参数另做JFR/GC配对。节点堆512m–1536m，客户端128m–512m。JVM/命令和窗口epoch在JSON。

线程与连接共同递增是供给档位比较，未按单因素实验定位根因；不能把速度下降归因于某个业务方法。闭环256上限和发压供给不足存在coordinated omission，未按固定到达率校正。实际网络是本机loopback。
