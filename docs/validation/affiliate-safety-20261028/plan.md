# 返佣安全与规模验证计划

基线：当前 master `6b5b4b04d`，JDK 27 / PostgreSQL 18.4；不回退或重跑旧提交。只修改 Gateway 返佣旁路及其迁移、测试和文档，不改撮合、风险、手续费计算与资金 Core。

资金门槛：每笔佣金池等于所有层留存之和；任意层累计比例不因碎片成交丢失；费用重复/并发不能多记；资金未知结果使用原身份；租约过期的旧执行器不能覆盖新执行器结果；结算单金额必须等于关联应付；异常事务不得推进消费游标。

稳定性门槛：树形关系唯一上级，循环和历史重叠必须拒绝；采用迭代遍历，不依赖 Java 调用栈；深链和单次事务有资源/时间上限，超限整笔暂停、不截断分钱；每次处理有界、不同产品可推进，积压和异常有进度与诊断。

数据库旁路专项：固定种子 20261028；宽度 10000，深度 8 / 128 / 1024，全部合作份额 100% 以覆盖深链末端仍有金额的最坏情况；每组先预热 3 笔、测量 20 笔实际 PostgreSQL 核算提交。测量核算终态数、p50/p90/p99/max、JDBC 语句准备次数、主线程分配、GC、进程 CPU 和 SQL 执行计划；另用 JFR profile 采样。费用、游标、佣金金额在退出前对账。宽团队查询、批量成熟结算另设用例。隔离数据库以 hardening 命名，结束后删除。

这是返佣数据库旁路专项，不是正式 Aeron 交易容量验收；不报告订单 TPS、成交对吞吐或三节点容量。真实 Core 资金恢复与实际费用观察单独回归；没有执行的网络/产品/长期场景明确记为未测。JFR 归档 summary/view 与摘要，原始录制控制在 64 MiB 内并清理。

待证实的实现方向：将沿路径的逐层数据库往返合并成有界路径快照和批量写入；将各层累计舍入做成持久化状态；消费按产品串行、不同产品隔离，读配置共享锁而写配置独占；限制准备/认领批次、增加租约隔离与重试退避；对查询和异常路径设置明确资源保护。具体改动以测量和回归发现为准。
