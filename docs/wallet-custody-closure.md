# 钱包与 custody 资金闭环

本轮已完成本地资金、故障、并发和跨端验证；命令、证据与未测范围见 [专项记录](validation/wallet-closure-20261030/README.md)。

## 用户金额与账务

申请金额是 Core 总扣款；平台手续费从申请金额内扣，净到账 = 申请金额 - 平台手续费。新请求须先调用 `POST /api/v1/wallet/withdrawals/quote`，确认返回的金额及 networkRevision，再按该版本提交。币种上架、网络开关、最低额、整数会计单位和链精度在服务端校验。配置变化要求重新报价；既有请求按原报价快照恢复，不重新估值、选择源地址或计费。

确认成功的收入在 gateway_wallet_withdrawal_fees 以提现主键唯一登记，与状态和事件同事务提交。永久拒绝或已确认失败退回原总扣款，不收平台手续费。实际链费由 custody 的 Gas 账户、用量及 NETWORK_FEE 账务承担；不能把平台固定费或配置预留当成实际链费。

## 租户本金池与提现用户

用户权益以 Core 可用余额为准。新交易所提现统一 `TENANT_POOL`，请求 `custodyAddressId=null`，受益人固定为已认证用户的 `subject=user:<ID>`；客户端不选择出资账户。custody 按租户、链、资产锁定虚拟池账户，排除全部 Gas 账户，仅将可用本金不足部分划入池，逐来源借记、池贷记审计、冻结与受理回执原子提交。资产看板统计池余额但不把虚拟账户算作充值地址。

物理出款沿用租户归集地址，与账本扣款账户分离。明确失败释放回池，之后可用于另一用户的提现，不重新移动或重复释放已占用的来源资金。控制台保留 ADDRESS 出款，须独立填写提现用户并在二次确认时显示；提现历史直接按订单 subject 筛选。受理与拒绝指纹同时绑定 fundingSource 和 subject，其他用户或资金来源的回执不能授权入账或退款。

## 跨系统提交与恢复

本地意图先提交，之后使用原 Core 引用扣款；钱包请求使用原外部引用和净到账。custody 接受订单、冻结、事件、审计及永久幂等受理一并提交。重试先重放原受理，不受后续网络停用或新增赤字改变。

只有 `POST /custody/api/v1/withdrawals/resolve` 生成并持久化的、键和请求哈希匹配的拒绝凭据允许退款；该操作与创建竞争同一主键，拒绝之后不能再创建同一意图。HTTP 4xx、超时或 GET 暂无结果均不授权退款。链上失败退款还要求原用户、资产、链、净金额、地址及引用吻合，以及已释放本金的终态凭据。

退款先独立提交授权凭据和 REFUND_PENDING，再以原 Core 引用退款，最后独立提交 REFUNDED；网络对账不持有数据库事务。Core 已退款但响应丢失时仍保留待退款凭据，重试不能产生第二次入账。

恢复任务覆盖 PROCESSING、DEBIT_UNKNOWN、DEBITED、BROADCAST_UNKNOWN、SUBMITTED、FAILED_PENDING 和 REFUND_PENDING。恢复任务使用有界、按到期顺序轮转的数据库领取租约；多实例不会因一批故障单长期挡住其他单，进程崩溃后租约到期仅恢复原请求。租约和时间不能授权退款。未知 Core 调用沿用同一幂等引用，未知 custody 调用沿用同一请求，已受理订单精确按 externalReference 对账；身份不一致或矛盾终态停止推进并保留审计。

普通 EVM 广播之前提交 nonce、签名字节和业务哈希；RPC 故障转移、响应丢失或进程重启只重播同一份字节，不换 nonce。只有采用该持久发送协议且没有哈希的过期领取可以恢复排队。确认成功/失败均校验原哈希、规范区块与确认数；失败释放本金，同时结算真实 Gas。

## 客户端与接口

Web/App 展示总扣款、平台手续费与净到账；原请求和报价在提交前持久保存，安全验证码不保存。未知结果只能查询或重试原引用；用户查询已提交请求不再消耗验证码。精确 subject 查询在 custody 分页前执行，外部引用查询也为精确匹配；search 不再承担用户隔离。

签名 API 同步增加 `GET /sapi/v1/capital/withdraw/quote`，提交接口要求 networkRevision，采用相同的内扣口径、风控和恢复。

## 部署与历史对账

先停止创建新提现，完成 custody 数据库变更并发布支持永久受理/resolve 的 custody，再发布 Gateway 与客户端。Gateway 迁移见 `deployment/migrations/20261030-wallet-withdrawal-fees.sql`。历史单的平台费回填为零，保留原扣款与原到账；network_id=0 仅标记该历史单没有报价快照，不用今天的配置追补收费。

升级前必须核对原审计报告中的旧 REFUNDED / BROADCAST_UNKNOWN 单与实际链上结果；本轮不读取生产数据，不自动冲正历史资金。旧版本已经广播但丢失哈希的交易不能通过换键或换 nonce 恢复，需要按地址与链上记录核对。数据库缺少旧受理凭据时不得猜测拒绝或删除订单唯一约束。

回滚时先停止新提现并保留所有新快照、受理凭据及收入流水；不得恢复以 HTTP 4xx 自动退款的旧实现，也不得回退或清空新的财务字段。现有受理、链上确认、Gas 对账和回调仍需继续运行。
