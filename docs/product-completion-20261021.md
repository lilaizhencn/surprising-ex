# 六产品线功能与验收进度（2026-10-21）

本轮按资金幂等、原请求恢复和产品隔离检查现货、U 本位永续、币本位永续、U 本位交割、币本位交割、期权，并保留 C2C 的独立验收边界。表中“本轮补齐”不代表该产品全部页面和真实设备场景完成。实际命令、结果及清理见 [验证记录](validation/product-recovery-20261021.json)。

## 本轮业务改动

1. `CommandFingerprint.Calculator` 恢复 canonical-v1 的 SHA-256。资金命令的指纹在快照和已提交回执中保存；先前同版本更换为 FastHasher 导致协议固定向量和六条产品线的固定快照幂等失败。保持原字节字段、原协议向量、原快照样本及槽位/缓冲区复用，只保留一种规范计算规则。新增的冲突检查要求：原请求重放返回 DUPLICATE，同一身份改变金额仍返回 IDEMPOTENCY_CONFLICT，资金和业务哈希均不能变化，再次快照恢复后仍成立。
2. Web 的 `state/pendingOrders.ts` 将普通单笔下单/撤单和条件单/OCO 的原身份恢复扩展到全部六产品；API 沿用既有 owner-bound realtime 回执。专用 `close-position` 和普通下单共用 `submitSingleOrder` 的持久化与确认逻辑，五条衍生产品线的一键平仓不再绕过恢复保护。发送前保存，未知结果保留原身份，存储失败不发送；刷新后只查询原请求，账户变更不能发出旧账户查询。
3. Flutter 的 `ProductMode` 对全部产品恢复已保存的普通单和条件单身份，补齐永续单笔下单、撤单及条件单丢响应的重建恢复。保护单 UI 与持久恢复分开：五条衍生产品支持持仓 TP/SL 双腿 OCO；现货不会因恢复开关改变而出现需要衍生仓位的 TP/SL 表单。现货既有条件单的撤销仍可按原身份恢复。
4. Flutter 下单价改为对所有产品按合约 `quoteScaleUnits`、`priceTickUnits` 及原始输入字符串换算，不再将衍生品固定当作 1e8 或先转 double；最优价、盘口点击与加减价同样用整数/BigInt 格式化。无精度或不符合步长时在保存意图和发送前拒绝，不制造一条实际未发出的待确认请求。引用价格的 tick×步长先用 BigInt 相乘，防止 int64 溢出；显示层近似值不再用于提交订单。六产品真实 loopback HTTP 验证 18 位小数对应的整数价格原样发送，320px 深浅主题验证 BBO 与加减价不丢末位。离线展示样本显式声明自己的精度，不向真实缺失元数据的合约猜填 1e8。
5. 扩大回归中发现的测试问题分别校正：现货市价测试按当前协议写入保护价格，继续核对 IOC 不挂簿及资金释放；并发测试保留第一次完成调用已经返回的最终回执，避免再向已回收槽索要第二份结果。另保留无保护价格必须拒绝的测试，未放松生产准入。客户端测试使用明确的内存设置存储，等待请求真正发出后再切账户/产品；条件单成功样本补齐实际原用户、永久合约和请求号，未知与明确拒绝分别验证。

## 证据边界

浏览器脚本 `surprising-ex-web/scripts/product-request-recovery-qa.mjs` 运行真实 Chrome、生产 HTTP 适配器和 localStorage，通过显式受控传输验证刷新、未知回执、原身份、账户隔离和仅一次 POST；不连接真实 Core，不作为资金记账或生产 UI 全流程的证据。Flutter 运行真实 AppState/组件与注入的契约响应、设置存储；320px 深浅主题验证 OCO 输入、精度、重复提交锁定及未决档位移出草稿，不等于 iOS/Android 真机安装。

Core 的资金、撮合、生命周期和快照检查在隔离导出的已提交源码加本次改动上运行，未纳入其他算法单工作区改动。历史固定向量及快照字节保持不变。JMH 只记录固定指纹计算的局部耗时和分配，错误 FastHasher 基线不能当作同等业务语义的性能目标，也不代表整机 Core 吞吐。

本轮 Core 全量运行 1886 项，1884 项通过、2 项条件跳过；随后开启统计配置，单独补跑其中的撤单资金释放检查并通过，剩余 1 项为 Linux CPU 绑定检查。Gateway 63 项、Web 375 项及浏览器受控传输 70 场景通过；Flutter 在隔离源码和现有工作区均为 447 项通过、11 项显式实栈配置缺失而跳过，两处静态分析均无问题。Web lint 与生产构建退出码为 0，仍有既有的信息级诊断和包体积提示。

JMH 的 canonical SHA-256 借用槽位路径约为 255 ns/次（余额命令）及 3559 ns/次（20 笔最大批次），本次测量无 GC；分配采样仍有约 0.002/0.022 B/次，不能宣称绝对零分配。持有独立指纹对象的路径约分配 64 B/次。此结果保留了正确的历史请求身份，同时明确记录其计算成本。

## 升级与数据边界

不新增 SQL、Kafka topic、Core 查询或独立服务；交易和结果查询继续走现有 Gateway/realtime。前端请求恢复依赖此前已提交的 realtime 回执导出、迁移及必要历史回补。

错误 FastHasher 已写入的快照/回执不能在缺少原始命令时猜测改写。本轮不会尝试两种哈希后将冲突当成重复，也不会删除资金幂等记录。升级前应在隔离数据副本中从原 Archive 重建规范指纹并核对资金；此次本地测试不代替服务器现有数据的升级验收。

本轮不发布远端服务、不安装 APK；不删除其他任务的数据库、进程或未提交改动。
