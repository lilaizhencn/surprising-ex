# 订单本地事实状态与查询投影

普通订单的开放状态属于订单用户分区事实流。`OrderUserStateService` 按
`ProductLine:userId` 使用单写入 lane，将下单、账户预占结果、撤单和撮合结果按 WAL 序号写入
RocksDB，再生成用户订单状态快照。

数据库中的 `trading_orders` 只作为异步查询投影、启动恢复和审计数据。`OrderStateProjectionWorker`
在本地状态序号推进后替换对应用户和产品线的投影，并且只有数据库事务成功后才推进投影水位。
投影延迟、数据库不可用或查询索引缺失，都不能被解释为“没有开放订单”，也不能影响下单、撤单、
撮合或资金裁决。

订单查询优先读取本地用户快照；跨节点查询可以读取数据库投影，但必须明确返回投影延迟或未就绪，
禁止把数据库结果写回事实状态。Redis 仅可作为查询加速或跨节点协调投影，不能作为订单事实源，也
不能在 Redis 失效时回退到数据库执行交易动作。

## 恢复与幂等

启动时先打开本地 WAL 和状态库，按连续序号重放未应用事件；序号断裂、事件指纹冲突或状态损坏时
该用户分区保持不可用。相同 `eventId` 只能接受相同指纹，重复 Kafka 消息不会重复应用。数据库
投影水位落后时只重放完整本地快照，不会反向覆盖本地事实。
