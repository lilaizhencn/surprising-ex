# 后台业务配置与热上线

## 合约维护

后台“产品市场”按产品线新增草稿，统一维护资产、交易单位、费率、风险档位、资金费、交割与期权字段以及外部行情来源。保存请求携带修改原因和预期版本，`InstrumentValidator` 校验产品规则，存储事务保存配置及变更记录。冲突返回 409，非法参数返回 400；已存在合约的资产、数量单位、价格单位及到期身份不能重新解释。

`InstrumentCoreSyncService` 自动把目录版本同步到 Core，并向后台报告已应用版本。`DRAFT` 不进入公开目录，`PRE_TRADING` 可展示，`TRADING` 才允许下单；后台必须以同步状态确认是否已生效。普通业务命令和快照恢复不再封闭合约注册入口。空产品线允许启动后从后台新增首个合约。独立手工播种 Core 合约的 CLI 已移除，避免绕过后台状态、单位校验和风险预算管理。六产品线保持独立配置、账户、事件和 Core 状态。

## 价格、资金费与生命周期参数

`PriceBusinessSettingsService` 以 `price_business_settings` 为产品线价格业务参数的权威来源，字段定义同时提供管理页面的标签、提示、类型和范围。`LifecycleBusinessSettingsService` 以 `lifecycle_business_settings` 保存资金费、强平执行、保险与 ADL 参数。保存采用版本比较，数据库成功后才替换运行参数；其他实例定期读取版本变化。调度任务从当前配置读取间隔，外部行情连接支持初始关闭后直接启用，无需重启。

数据库、Kafka、Aeron、节点标识及密钥属于部署连接参数。价格和生命周期业务配置不再由对应 YAML/业务环境变量覆盖。升级已有环境时，必须先将实际运行的业务参数迁入新表，不能直接用新安装默认值替换现有策略。迁移入口位于 `deployment/migrations/20261005-price-business-settings.sql` 与 `20261005-lifecycle-business-settings.sql`。做市定义及公共参数沿用 `20261005-admin-contract-settings.sql` 的数据库管理入口。

## 权限与操作反馈

日常配置由一个有对应权限的管理员完成，仍校验参数、版本、状态迁移并记录审计。余额调整、保险资金调整及交易维护等干预保留审批。合约列表请求与行情健康请求分别处理，行情健康不可用时明确提示，不阻止合约维护。仅邮箱注册的管理员使用邮箱显示身份。

## 验证边界

`SixProductLineContractLiveTest` 为显式启用的真实服务验收，只接受本机 `sixline_live` 数据库。它创建隔离测试账户，通过真实认证、后台请求、Core、做市、用户交易与 WebSocket 验证草稿、上线、交易开关、编辑、版本冲突、非法单位、当前风险金额以及交易前后用户/做市/平台资金守恒；通过进程启动时间确认合约变更没有重启服务。资金注入仍使用双管理员批准。测试账户 JWT 校验有效期为 604800 秒。

Core 的现货最小资产单位与快照恢复由 `CoreSpotAssetUnitsTest` 验证；业务配置数据库保存、重新加载、旧版本拒绝及环境变量不能覆盖业务值由两个业务配置集成测试覆盖。真实交易验收不自动代表交割到期、期权行权、强平和 ADL 全链路均已验收，最终范围以验证记录为准。

## 期权外部报价契约

期权来源使用 `OPTION_RISK_TICKER`，报价币种必须与配置的目标计价币相同。HTTP 与 WebSocket 使用同一消息格式：`symbol` 必须与后台“来源交易对”完全一致，`markPrice` 是期权权利金，`indexPrice` 是标的指数，`sameExpiryForwardPrice` 是同到期远期价格，`expiryTime` 为 ISO UTC 到期时间，`timestamp` 为报价时间的 Unix 毫秒数。三种价格须为正数；标识不符、未来时间、过期报价或合约到期不符不会用于发布有效标记价。

多来源按通过新鲜度和异常值校验后的权重聚合，不能把标的指数当作权利金，也不能用永续资金费收敛价伪造同到期远期。`OptionPriceReference` 仅是价格输入传递边界，不保存另一份业务配置。期权 `nextFundingTime` 为 null，价格审计迁移 `20261005-option-price-reference.sql` 允许该值为空，完整三组输入保存在已有的审计 JSON 中。

## 订单价格保护与算法订单规则

`OrderBusinessSettingsService` 从按产品线隔离的 `order_business_settings` 读取价格保护、行情有效期和算法订单执行限制。后台产品市场的“产品线订单规则”提供统一维护入口；完整请求校验字段集合、整数/布尔类型、数值范围和版本，拒绝缺失字段、隐式类型转换及旧版本覆盖。网关只从环境读取 Kafka、Aeron 和发送超时等连接参数，业务参数不接受环境覆盖。

价格保护通过 `InstrumentCoreSyncService` 写入每个合约的 `CoreOrderProtection`；交易核心使用相同规则检查标记价有效期、限价价格带、市价保护和冻结金额。后台以合约同步状态确认 Core 已采用新规则。注册协议 V5 保存保护规则；快照字段 29–33 保存该规则，使用非历史默认值时要求最低 reader revision 3，避免旧版本忽略交易边界。旧日志按其原有规则重放。算法扫描从当前数据库配置读取间隔，无需重启。

2026-10-06 测试服务器部署预检发现旧 Core 已退出，原因是强平批处理读取到过期标记价时异常穿过提交阶段。`OrderedCommitCoordinator` 将这类过期 action 计为 obsolete，保留账户 Lane 提交确认并等待新风险任务，不按旧价格执行强平。`RiskBatchBudgetTest` 增加同步/异步及快照恢复场景，断言过期任务不撤单、不改变账户资金和持仓，并保持重放结果一致。该测试 15 项通过。

## 历史成交导出恢复补充

线上验证发现，强平批次的账户动作跨越不同 Lane 时，取消预算耗尽或动作已终结的分支没有确认全部预期 Lane，导致独立成交导出重放失败。批次现在为每个已验证 action 登记账户确认，即使该动作不改变订单或余额，也与不可变撮合结果的 Lane 集合保持一致。回归使用用户 1 和 7（默认拓扑分属不同 Lane），覆盖预算分段、同步/异步、已终结动作、快照与 `CommittedTradeReplay`；修复前两个场景复现失败，修复后相关资金与恢复测试 57 项通过。

`20261006-maker-draining-event.sql` 为旧库做市运行事件约束补充 `STRATEGY_DRAINING`，与初始 SQL 保持一致，避免暂停清理事件被数据库拒绝。
