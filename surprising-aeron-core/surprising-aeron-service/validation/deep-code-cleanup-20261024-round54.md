强平步骤从12个字段减为4个：canceledCount、userId、assetId、positionKey，全部为原语。用户身份仅在回执中保存一次；强平正文已改为局部输入，不再为读取用户身份延长整份记录的生命周期。orderIds数组仍在校验阶段创建并逐项确认用户，随后用于原撤单流程，未为减少字段改成提前执行撤单或增加遍历。

单笔Owner保存的Lane用于原dispatchControlLanes/executeLaneMutations，结果在原pollControlLanes完成后从同一槽读取。账户读取受当前Lane作用域限制，拓扑由运行时final引用固定；没有新增派发、跨Lane读取、锁、状态副本或第二份资金结果。

静态逐字对照确认：原产品、强平阶段、撤单游标、价格、撤单用户、持仓及资产校验正文保留；计划失效、撤单解冻、游标继续和最终平仓的账户操作正文保留；executeAccountLiquidation及之后的全部资金公式和约束未修改。原准备阶段只检查并构造输入，没有外部调用可在prepare和apply之间介入，因此合并不改变业务操作次序。Owner实际撤单计数仍决定修订增量，资金回执仍通过原控制结果交给账本。

杠杆和持仓模式的Lane处理器已经返回“是否实际改变”，true分支的Owner原本就会先成功执行Math.incrementExact再比较开始前修订。新的变化标记直接取该实际回执，不需要传递并保存另一份产品修订。账户规则、敞口阻止条件、杠杆/档位上限、生命周期冲突、保证金计算和修订溢出预检保持原样。DirectCommandSlot.beforeRevision仍用于整个命令的变更/回滚；风险扫描的同名字段仍用于判断扫描是否改变状态，两者都有独立用途并保留。
