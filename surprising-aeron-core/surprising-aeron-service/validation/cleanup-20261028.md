# Aeron 最小撮合 DTO、订单复制及状态转发清理（2026-10-28）

本批删除 **1 个生产 DTO 类、11 个无业务消费者的手写方法/构造器**，4 个 service 生产文件净减少 **188 行**。旧 DTO 中仍被真实撮合使用的滑点规则移入原适配器私有方法，没有删除产品规则。记录类的自动访问器及 Object 方法随类移除。上一批账户转发与旧恢复资源清理记录见 `6b5b4b04d` 中本文件。

## 业务链路与删除依据

账户完成准入后交出真实 `ResolvedPlaceOrder`，或将订单冻结成 `OrderRuntime`；Matcher 在既有发布租约和同步命令范围内执行撮合、记录证据并交给账户结算。状态变更保留既有成交事实和费用，只推进状态、版本及原日志元数据。

- `CoreMatchingOrder` 的实例仅用于测试。生产中只有 Adapter 的两个真实入口读取其静态滑点规则。将规则留在实际消费者 Adapter 中，删除整个记录类及其三个构造入口，并删除依赖它的 `placeDirect`、`placeNative` 和 `orderType` 重载。真实准入/冻结订单入口及其异常传播、分片检查、证据和命令范围清理不改动。
- 原生订单簿、管线、快照与结算计划测试使用现有 `DirectMatcherTestInputs` 构造真实准入结果，直接进入生产 Resolved 入口，没有把旧 DTO 搬到测试目录或再建替代生产模型。测试明确区分现货、U 本位永续及交割，保留实际产品及冻结资产规则。该输入辅助只准备订单簿测试，不据此宣称已完成账户资金结算。
- U 本位永续/交割仍为 100 ppm，其余产品规则仍为零。滑点测试改为真正的 U 永续和交割准入输入，覆盖两产品买卖双向，以及舍入不多成交一跳的边界。
- 删除 `OrderRuntime.withExecution`、两个 `withFill` 及只带状态/版本的 `withStatus`。它们是测试复制 API，带完整元数据的状态变更仍有真实生产消费者。后者直接构造新状态，原位状态变更也直接检查并更新状态和元数据，不再转发为新增费用为零的成交操作。
- 状态变更不重新计算已经成立的成交量恒等式、不执行费用加零；状态/版本和提交元数据的实际输入校验仍保留，成交金额精确加法仍在真实 `applyFillInPlace` 中。原创建时间、负费用返佣、累计成交值高低位及提交位置继续保留。
- 索引、准入和快照测试的数据复制由已有 `CoreStateTestFixtures` 明确构造。只验证已删除 immutable fill API 的旧用例随 API 删除；现有真实取消/元数据测试继续核对前值不变，并补充非法元数据不改变成交和费用的拒绝路径。
- 删除只供测试/基准默认填指数和远期价格的 `ResolvedPlaceOrder` 构造重载，相关调用明确给出两项价格。完整构造、复制及复用初始化的实际业务校验保留。

没有新增生产类、接口、派发阶段、集合或状态副本。没有改协议字段、价格精度、冻结、结算顺序、幂等或快照格式。当前脚本与源码导航没有依赖被删除的撮合 DTO；README 同步真实输入和状态更新职责。
