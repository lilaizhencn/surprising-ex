# Aeron 实时协议边界

## 复制命令与查询状态的边界（2026-10-24）

Core schema 为 16。算法命令 v6 分为 `CoreAlgoOrderCommand.Create` 和 `Update`，更新仅携带预期版本、本次生命周期变化和可选新增子单。
触发创建 v5 使用 `PlaceTriggerOrderCommand`，不传查询状态中的初始生命周期、时间、版本、费率或重复归属；Core 从命令头、Cluster 时间和配置初始化。
延时全撤命令 v5 从命令头取得用户，SET只携带原业务时间和倒计时，Core用检查溢出的加法推导截止时间。完整查询、实时事件和数据库状态编码保留其实际业务字段。
倒计时COMPLETE不再携带两项成功数量，命令记录剩5组件；查询/状态编码v3和Core状态各6组件，快照v53不写计数字段7/8。预期修订、真实截止时间和更新时间继续保存；Gateway沿同一修订认领、完成或重试，三十秒超时资格由Core现有时间事实判断。
算法更新命令v6与状态/投影编码v5不再保存完成时间，分别剩8/28组件；创建意图本身不变。倒计时命令仍v5，SET真实时长输入继续使用；仅状态/查询v3省略原时长副本。快照v53不写算法字段23和倒计时字段3，既有实际创建/更新时间、截止、版本及恢复边界保留。
注册合约类型由产品线唯一确定。注册只读取当前V10，编码与解码都要求明确产品上下文：数量步长只属于现货，价格单位与结算精度只属于反向合约，到期只属于交割与期权，类型和行权价只属于期权。
现货不传五项衍生品订单保护配置，Core配置为空；现货市价的用户保护价格边界仍保留。
现货没有衍生品风险段；衍生品使用6字段 `CoreInstrumentRiskLimits`，期权不传标的最大杠杆。风险值在接入处按真实产品校验，期货不受期权因子约束，期权不受杠杆约束。
每个 `CoreRiskLimitBracket` 值类型仍有5字段，实际每档只编码4个long、32字节：上界、初始/维持保证金率，以及期货最大杠杆或期权因子。编号和下界由列表确定。
命令不再携带合约类型码、现货虚拟风险档或标的级维持保证金率；实际风险档中的维持保证金率继续保留。交易状态快照v53采用相同产品边界，风险档保留共同字段3/5/6，期货增加字段4、期权增加字段7；退役字段1/2不写。触发查询和状态只读取各自当前V3，算法状态视图只接受已初始化的真实时间。
算法类型编号仍为TWAP=0、ICEBERG=1。ICEBERG不携带间隔long：命令v6和状态/投影编码v5按类型省略，快照v53不写算法字段10；TWAP仍要求真实正数间隔，未知类型沿原非负编号/正数间隔边界处理。当前布局直接拒绝旧命令与状态编码，不增加读取回退。
算法内部记录只保存TIF，删除PostOnly布尔副本；TWAP=0固定IOC，命令v6/状态v5不写该TIF，算法快照不写字段15及TWAP字段16。ICEBERG保留真实TIF；HTTP用户PostOnly选择在网关转成GTX，响应仍提供实际结果。普通订单的PostOnly字段与准入约束不随本项删除。
风险冷/热结果不再保存等级副本，按已固定的风险比例与原阈值提供同名读取；交易快照不写字段9，风险比例字段8仍必填。对外查询和实时等级字段保留，业务哈希继续使用固定等级编号。
普通订单冷/热状态不再独立保存原请求价和剩余量，交易快照v53不写字段6/10。剩余量由总量和累计成交量推导；原请求价在衍生品MARKET为0，现货和LIMIT取实际撮合价。真实撮合保护价仍写字段7，查询/实时/响应仍提供原请求价及剩余量，撤单历史、费用及成交额精度保留。
未接入实际消息链路的 `CoreInputEvent/Codec` 和消息分类的数字码已删除；现用 `CoreMessage` 入口及分类枚举保留。
行情编码与解码都要求产品上下文：仅期权携带远期价，其余产品保留标记、指数、最新价、序号和时间，共5个long。
交易状态快照同样只为期权保存远期价字段4，非期权运行态固定0；缺实际字段或存在多余字节仍拒绝，不读取旧布局。
划转只读取当前显式收付款用户的 v2，资金指纹严格比较；用户确认无需旧日志/快照，旧格式直接拒绝。

本轮随服务、网关、工具、基准和实时投影的 17 个相关模块执行 `-am -DskipTests clean test-compile`，干净编译通过；未执行测试、交易、数据库或恢复。

## 零金额账户初始化（2026-10-20）

`BalanceAdjustmentCommand` 允许 `deltaUnits=0`，沿用现有 `ADJUST_BALANCE` 字节格式与资金幂等边界。首次命令建立真实 Core 用户/资产记录，已有账户金额保持不变。它用于 C2C 首次开放前准备不可登录的内部托管及手续费账户；不发行资金、不创建 SQL 钱包余额。重试保持原命令身份，查询继续由 realtime 提供。旧 Core 的参数校验会拒绝零值，须先升级 Core 再调用 Gateway 初始化入口。

协议编解码，以及六条产品的零金额建账、原命令重放、已有余额不变、快照恢复与原划转生命周期共 43 项定向测试通过。该结果不代表本轮 C2C 真实资金闭环或三端交互已经验收。

## 数字币对 ID 的解码缓存修正（2026-10-18）

`TradingCommandCodec.decodeAsciiSymbol` 统一按原始字节内容使用既有256槽缓存，覆盖 `10000`、`10127` 直至正整数上界等币对ID。移除绕过该缓存的数字解析分支：它调用仅缓存1–1023的 `InstrumentIds.canonicalString`，使较大ID每次重新生成字符串；该无调用的辅助方法及小ID字符串缓存也已删除。数值字段的VarHandle解码保留，协议字节格式不变。

缓存仅保存文本解码结果，命中时复用不可变String；槽位冲突时核对完整内容并替换，输入帧复用不会改写已解码文本。它不替代币对注册表或业务准入校验，不保证冲突/首次解码零分配。未新增缓存、线程或执行阶段。

新增回归覆盖独立值与借用槽解码、1/1023/1024/10000/10127/999999/2147483647、输入复用及10000/10088槽位冲突；修复前7个参数中5个大ID失败，修复后协议模块249项全部通过，依赖产品API测试通过。按用户要求未做压测、JMH或JFR，不据此声称P99或吞吐改善。

## 有界 ByteBuffer 解码（2026-10-08）

`RealtimeFrameCodec.decode(ByteBuffer)` 只读取调用者 position/limit 之间的帧，不修改调用者游标。支持堆、直接和只读缓冲区；帧大小、字段长度、产品/消息类型、身份及尾部多余字节仍校验，线上的 v1 字节格式不变。原 byte[] 入口委托同一个解码流程。

解码结果不保留传输缓冲区。payload 复制为独立数组，`RealtimeFrame` 的构造和公开访问仍保留防御性复制，因此修改输入缓冲区或调用者取出的数组不会改写已交付事件。本轮仅去掉 Receiver 在解码前复制整帧的成本，未为省复制改变 record、公共 API 的不可变性或新增共享状态。

HotSpot JDK 27 单线程组件采样：同一解码器读取直接缓冲区，比较先复制整帧到 byte[] 与直接按 ByteBuffer 解码；预热 10,000 次，测量 100,000 条 2,048 字节 payload，同时录制有大小上限的 JFR，并用 ThreadMXBean 统计调用线程。分配量从 650.330MB 降至 438.857MB（约 32.5%），CPU 时间从 157.528ms 降至 129.511ms。此为复制边界的隔离采样，不代表真实服务器吞吐或网络延迟。

测试覆盖六产品和全部实时消息类型、非零缓冲区偏移、堆/直接/只读缓冲区、截断以及输入/输出修改隔离；共享 codec、六产品撮合/实时输出/快照恢复回归通过。原始 JFR 和临时程序汇总后清理。


### 借用命令的终态响应生命周期（2026-10-14）

解码槽通过 `CoreMessage.ownedResponse` 生成一份只读终态响应，并通过 `responseHeader` 生成独立的RESPONSE Header；两者共享输入帧的租约，响应Header不会改写请求Header。异步发布者在交接前调用 `retainForEgress`，编码或丢弃后调用 `releaseFromEgress`。最后一个消费者释放前，解码器不能复用输入、响应Header或响应元数据。调用 `CoreResponse.data()` 得到的独立字节副本可长期保留。

独立构造的 `CoreMessage` 继续生成独立响应值；只有显式租用的解码槽允许复用。一个租约只能准备一次终态响应，重复准备会拒绝。验证见 [响应槽及跨模块功能记录](../../docs/validation/leased-response-position-slots-20261014.json)。


### 命令槽的 UTF8 客户端订单号解码（2026-10-15）

`TradingCommandCodec.decodePlaceOrderInto` 保留原帧范围、64 字节文本上限及订单字段校验。仅解码槽中的 `PlaceOrderCommand` 在首次遇到非 ASCII 订单号时，取得自身的标准 UTF8 decoder、64 字节及 64 字符工作缓冲；随后复用这些转码缓冲，并创建独立的不可变 `String`。ASCII 及独立值入口沿用原 String 解码，不新增名称缓存、ThreadLocal 或线程。最终 String 存储及 JDK 的 compact-string 转换仍会分配，不能称为零分配。

29 个协议用例和 166 个直接受影响的服务用例通过。随机字节验证在一个用例内比较 5,000 组输入与 JDK 原解码结果，另覆盖非法代理编码、截断多字节、空值、最大长度、保留旧值和槽位复用；跨服务验证覆盖六产品线及身份、查询、成交、风险、资金、批量、划转和实时输出。见 [UTF8 解码功能验证](../../docs/validation/utf8-command-text-20261015.json)。未运行快照/恢复、wallet 或真实节点压测；分配诊断数值仅保留本地，完整 Owner 迁移及 Core 百字节目标仍未完成。

### 交易命令槽与变长载荷（2026-10-18，验收中）

`CancelOrderCommand`、`AmendOrderCommand`、`ReplaceOrderCommand` 及撤单/改单批次沿用下单命令的显式借用槽。独立构造的公开值不可变；从借用项构造公开批次或替换单时复制为稳定值。`DecodedMatchingCommand` 只保存一份当前载荷引用，命令终态及所有消费者完成前不得清槽。单笔改单按原始数组范围解码，批次直接读取每项范围，不创建分帧数组或临时项集合。

`CoreMessage.payloadLength()` 是唯一有效载荷长度，`payloadUnsafe()` 可能包含未使用容量，调用者必须同时传入逻辑长度。`payload()`、编码、指纹、相等比较与哈希均只处理有效字节。`CoreMessageFlyweightDecoder` 对普通交易命令使用最大16KiB的2次幂容量桶，行政命令仍按精确长度复用；总共最多512个借用槽。Aeron回调到Owner的首次复制仍保留，不能借用回调结束即失效的传输缓冲。

删除非业务递增命令的线码1，后续消息线码不变，旧命令直接拒绝。集群探测工具只支持状态哈希查询或Lane指标查询。功能、分配和实际节点结果在根 `PERFORMANCE_VALIDATION.md` 中按本轮计划记录；本节不预先宣称验收通过。
