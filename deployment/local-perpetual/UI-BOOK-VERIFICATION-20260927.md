# 2026-09-27 本地永续页面与盘口验证

## 范围和业务流程

仅运行 U 本位永续 20 币对、六个现有服务及前端，未启动 wallet。Core 资金、撮合与快照源码未改动；工作区已有的 Core 修改不属于本轮。

- `QuotePlanner` 依据真实外部参考盘口、合约最小单位及库存额度生成 50 档目标报价。每档数量使用稳定的不同系数并结合外部数量，合计数量受仓位预算限制。
- `MarketMakerService.reconcile` 先补被吃掉的档位，再分批撤换旧报价；拒单时停止扩大撤单，避免周期性清空盘口。实际成交与拒单仍会影响实时档数，不承诺任何网络/资金状态下恒定 50 档。
- 本地模拟吃单逐单抽取方向和 1～10 steps 数量并检查库存，报价/吃单线程分别配置 100ms/150ms 轮后间隔。它是本地模拟流量，不是真实用户交易。策略为 Java PMM 实现，并非启动 Python Hummingbot 实例。
- `RealtimeRouter` 由路由线程维护每币对最多一个在途盘口查询，响应后移除、2 秒无响应可重试、断线清空；权威盘口仍属于 Core。防止重复恢复查询挤占私有账户快照。
- 前端新盘口 SNAPSHOT 替换旧基线，后续 DELTA 校验连续序号；支持断线恢复时较小的新快照序号，避免成交在动而盘口停留旧 epoch。
- 合约信息新增 24 小时量、额和单边持仓量，指数图标展示实际来源及计算过程；24 小时统计独立于图表周期。顶部紧凑单行，窄屏横向滚动，不挤出页面宽度。
- 下单区域开仓/平仓、逐仓/全仓、杠杆弹窗、实际 Maker/Taker 费率及保守可开数量；杠杆保存以服务响应为准。未登录只显示一个绿色居中入口，点击杠杆也有明确弹窗。移除单独 Quantity step 文案。

## 行情源中断与恢复

收尾观测到 Binance 9443 连接超时，三源不足导致标记价过期，策略安全降级；六服务进程存活不代表可交易。直接测试相同官方域名 443 收到实时 BTC ticker 后，更新初始化 SQL 及当前本地 20 条 Binance 源地址，重启价格服务。保留三源校验，不使用旧价格维持做市。官方端口说明：https://github.com/binance/binance-spot-api-docs/blob/master/web-socket-streams.md 。

恢复后再次连续观测 60 秒：20 币对均收到成交及盘口更新，每币对 422～660 笔成交、123～156 次深度更新；各侧最少 31 档，增量序号缺口 0。见 `pmm-ladder-restored.json`。三来源独立到达，个别币对仍可能短暂因标记价新鲜度检查降级；观测到恢复后自行继续报价，未放宽风控或声称外部网络永不中断。
